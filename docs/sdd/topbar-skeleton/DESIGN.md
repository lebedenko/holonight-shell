# DESIGN: Top Bar Skeleton

**SDD Session:** topbar-skeleton
**Feature:** Foundational layer surface and QML structure for the HoloNight shell top bar
**Status:** Design
**Last Updated:** 2026-05-21

---

## Overview

This document describes the architecture for the `topbar-skeleton` SDD session. The goal is to establish the minimum viable Wayland layer shell integration and QML component hierarchy that will serve as the foundation for all subsequent top-bar sessions.

The session delivers two tightly coupled subsystems:

1. **C++ Wayland integration** (`LayerShellManager`) — discovers all connected `wl_output` globals at startup, creates one `zwlr_layer_surface_v1` per output anchored to the top edge, and instantiates one `QQuickView` per surface to host the QML bar.
2. **QML bar components** (`src/qml/Topbar/`) — a modular hierarchy of five components rendering the static bar background, the Arch Linux logo on the left, and a live clock on the right, all colored exclusively from the system-wide `HoloniightPalette` singleton.

After this session the binary must launch on Hyprland, place a bar on every connected display, and be extended in later sessions by adding more `BarSection` instances without structural changes to the C++ layer.

## C++ Design

### `LayerShellManager`

**File locations:** `src/LayerShellManager.h`, `src/LayerShellManager.cpp`

**Inheritance:** `QObject` (not `QWaylandClientExtension` — see Key Decisions section)

**Responsibilities:**

- Register a `wl_registry_listener` via raw libwayland at construction time.
- When `zwlr_layer_shell_v1` global appears: store the bound shell object.
- When each `wl_output` global appears: record the output and, if the shell is already bound, call `createBar()` immediately. If the shell is not yet bound, defer until it appears.
- After the initial `wl_display_roundtrip()` completes, create bars for all outputs discovered in that roundtrip.
- `createBar(wl_output*)` — the core per-output factory (see below).

**Internal data structure:**

```cpp
struct OutputRecord {
  wl_output* output;                      // raw Wayland output global
  zwlr_layer_surface_v1* layer_surface;   // raw layer surface (from QtWayland wrapper)
  std::unique_ptr<QQuickView> view;       // QML renderer for this output
};

std::vector<OutputRecord> outputs_;
wl_display* display_;
wl_registry* registry_;
QtWayland::zwlr_layer_shell_v1 layer_shell_;  // generated wrapper; holds m_zwlr_layer_shell_v1
```

**`createBar(wl_output* output)` sequence:**

1. Construct a `QQuickView`. Do not show it yet.
2. Obtain the native `wl_surface` for the view's underlying `QWindow`:
   ```cpp
   auto* ni = QGuiApplication::platformNativeInterface();
   auto* wl_surf = static_cast<wl_surface*>(
       ni->nativeResourceForWindow("surface", view->handle()->window()));
   ```
3. Call `layer_shell_.get_layer_surface(wl_surf, output, layer_top, "bar")` to obtain a raw `zwlr_layer_surface_v1*`.
4. Wrap it in `QtWayland::zwlr_layer_surface_v1` and configure:
   - `set_anchor(anchor_top | anchor_left | anchor_right)` — pin to top, stretch horizontally
   - `set_size(0, 42)` — width 0 means "stretch to anchor"; height = exclusive zone
   - `set_exclusive_zone(42)` — reserve 42 px at top
   - `set_margin(8, 8, 0, 8)` — top=8, right=8, bottom=0, left=8
5. Commit the `wl_surface` (`wl_surface_commit`) so the compositor sends a configure event.
6. Call `wl_display_roundtrip(display_)` to block until the configure event is received. The configure event provides the actual width the compositor assigned.
7. Resize the `QQuickView` to `(configured_width, 42)`.
8. Load `qrc:/HolonightShell/Topbar/TopBar.qml` into the view.
9. Call `view->show()`.

**Configure event handling:**

Override `zwlr_layer_surface_v1_configure(serial, width, height)` in a thin subclass of `QtWayland::zwlr_layer_surface_v1` to call `ack_configure(serial)` and store the negotiated dimensions. Alternatively, handle via the raw C listener — either approach is acceptable as long as `ack_configure` is called before the next commit.

**Ownership model:**

`LayerShellManager` owns all `OutputRecord` entries via `std::vector`. The `QQuickView` unique_ptr destructor handles view teardown. The layer surface is destroyed via `zwlr_layer_surface_v1_destroy()` in `LayerShellManager`'s destructor before the registry and display are disconnected.

**Thread model:** Single-threaded. All Wayland calls happen on the Qt main thread. `wl_display_roundtrip()` blocks briefly at startup only; normal event dispatch is via Qt's event loop integration with the Wayland socket fd.

### `main.cpp` changes

Replace the current stub with:

```cpp
#include "LayerShellManager.h"
#include <QGuiApplication>

int main(int argc, char* argv[]) {
  QGuiApplication app(argc, argv);
  LayerShellManager manager;
  return app.exec();
}
```

`QGuiApplication` is correct — no widget subsystem is needed (see Key Decisions).

## QML Design

### Module and import paths

- QML module URI: `HolonightShell` (top-level, already registered in CMakeLists.txt)
- Topbar sub-module: `HolonightShell.Topbar` (achieved by placing files under `src/qml/Topbar/` and listing them in `QML_FILES`)
- Color singleton: `import Holonight` then `HoloniightPalette.<role>` — note double-i in the class name; the module is system-wide and pre-installed

### Component specifications

#### `TopBar.qml`

Root component loaded by each `QQuickView`.

```
Item {
  id: root
  width: parent.width   // bound to view geometry set by LayerShellManager
  height: 42

  BarBackground { anchors.fill: parent }

  RowLayout {
    anchors.fill: parent
    anchors.leftMargin: 12
    anchors.rightMargin: 12
    spacing: 0

    LogoSection { Layout.alignment: Qt.AlignVCenter }
    Item { Layout.fillWidth: true }   // center spacer
    StatusSection { Layout.alignment: Qt.AlignVCenter }
  }
}
```

No `radius` on the root Item — radius is owned by `BarBackground`.

#### `BarBackground.qml`

Renders the bar's base visual layer.

```
Rectangle {
  anchors.fill: parent
  color: HoloniightPalette.surface   // #161925 per design system
  radius: 16

  // 1px bottom border
  Rectangle {
    anchors {
      left: parent.left
      right: parent.right
      bottom: parent.bottom
    }
    height: 1
    color: HoloniightPalette.borderPassive   // maps to Border Muted: #565f89
  }
}
```

`radius` on a `Rectangle` clips only visible corners; the bottom border rectangle is drawn on top at the bottom edge, so its corners are square (which is correct for the inner border).

#### `BarSection.qml`

Generic reusable framed container with a default content slot.

```
Rectangle {
  id: root
  color: "transparent"
  implicitHeight: 42
  implicitWidth: container.implicitWidth + 16  // 8px padding each side

  default property alias content: container.data

  Item {
    id: container
    anchors {
      fill: parent
      leftMargin: 8
      rightMargin: 8
    }
  }
}
```

The `default property alias` pattern allows callers to write children directly inside `BarSection {}` and have them routed to `container.data`.

No border or glow in this session (deferred to `topbar-hud-polish`).

#### `LogoSection.qml`

```
BarSection {
  Row {
    anchors.centerIn: parent
    spacing: 6

    Canvas {
      id: archLogo
      width: 20
      height: 20
      onPaint: {
        var ctx = getContext("2d")
        ctx.clearRect(0, 0, width, height)
        // Equilateral triangle pointing up, centered
        var cx = width / 2
        var h = height * 0.9
        ctx.beginPath()
        ctx.moveTo(cx, height * 0.05)             // apex
        ctx.lineTo(cx - h * 0.577, height * 0.95) // bottom-left
        ctx.lineTo(cx + h * 0.577, height * 0.95) // bottom-right
        ctx.closePath()
        ctx.fillStyle = HoloniightPalette.onSurface  // or accent cyan
        ctx.fill()
      }
    }

    Text {
      anchors.verticalCenter: archLogo.verticalCenter
      text: "ARCH"
      color: HoloniightPalette.onSurface
      font.pixelSize: 13
      font.letterSpacing: 1.5
    }
  }
}
```

The triangle geometry uses a 0.577 multiplier (`1/sqrt(3)`) for a true equilateral. `onSurface` maps to the primary text role (`#c0caf5`).

#### `StatusSection.qml`

```
BarSection {
  Text {
    id: clockLabel
    anchors.centerIn: parent
    font.family: "JetBrains Mono"
    font.pixelSize: 14
    color: HoloniightPalette.onSurface
    text: Qt.formatDateTime(new Date(), "HH:mm")
  }

  Timer {
    interval: 1000
    repeat: true
    running: true
    onTriggered: clockLabel.text = Qt.formatDateTime(new Date(), "HH:mm")
  }
}
```

The initial text is set inline at property declaration time via `Qt.formatDateTime(new Date(), "HH:mm")`, so `Component.onCompleted` is not required.

### HoloniightPalette color mapping

| QML reference | Design system role | Hex |
|---|---|---|
| `HoloniightPalette.surface` | Surface | `#161925` |
| `HoloniightPalette.borderPassive` | Border Muted | `#565f89` |
| `HoloniightPalette.onSurface` | Text (primary) | `#c0caf5` |

These are confirmed from the design system's color table in `assets/dont-commit/HoloNight-Design-System.md`. The actual property names on `HoloniightPalette` are resolved at runtime from the installed `Holonight` QML module — if a name mismatch occurs at runtime, QML will log an undefined-property warning, which makes it immediately visible.

## Data Flow

```
Startup
  main()
    └── LayerShellManager()
          ├── wl_display_connect()
          ├── wl_registry_add_listener()
          ├── wl_display_roundtrip()     ← discovers globals
          │     ├── global: zwlr_layer_shell_v1  → bind + store
          │     └── global: wl_output (×N)        → createBar() for each
          └── [Qt event loop starts]

createBar(wl_output*)
  ├── new QQuickView
  ├── get wl_surface via QPlatformNativeInterface
  ├── zwlr_layer_shell_v1.get_layer_surface()
  ├── set_anchor / set_size / set_exclusive_zone / set_margin
  ├── wl_surface_commit
  ├── wl_display_roundtrip()             ← receives configure(serial, w, h)
  ├── zwlr_layer_surface_v1.ack_configure(serial)
  ├── view->resize(w, 42)
  ├── view->setSource("TopBar.qml")
  └── view->show()

Runtime (Qt event loop)
  QQuickView renders QML
    TopBar.qml
      ├── BarBackground (static, redraws only on resize)
      ├── LogoSection   (static after Canvas paint)
      └── StatusSection
            └── Timer (1 Hz) → updates clockLabel.text
```

The C++ layer has no runtime dependency on QML state. QML has no awareness of Wayland — it renders into a `QQuickView` whose native window is already bound to the layer surface before QML loads.

### QML sub-module path note

The `URI HolonightShell` registration places all QML files under the `HolonightShell` module root. Files in `src/qml/Topbar/` are accessible as `HolonightShell.Topbar.TopBar` etc. because Qt derives the sub-path from the source directory relative path. The `QQuickView::setSource()` call uses a resource URL (`qrc:/HolonightShell/Topbar/TopBar.qml`) which is stable regardless of install prefix.

## Key Decisions

### 1. One `QQuickView` per output — not a single spanning window

The `wlr-layer-shell` protocol requires a separate `wl_surface` per `wl_output`. A compositor assigns geometry, exclusive zone, and layer independently for each surface. Qt's windowing system does not support multi-output windows on Wayland in any meaningful sense — a `QWindow` is always associated with one native surface, which the compositor places on one output. Attempting to span outputs would require compositor-specific extensions not in scope.

Consequence: `LayerShellManager` maintains a 1:1:1 mapping of `wl_output` → `zwlr_layer_surface_v1` → `QQuickView`. Each view is fully independent.

### 2. Raw `wl_registry` listener instead of `QWaylandClientExtension`

`QWaylandClientExtension` is the Qt-recommended pattern for binding to a single protocol global. It works well for a single extension object (e.g., binding `zwlr_layer_shell_v1` itself). However, we also need to enumerate `wl_output` globals, which are not Qt-wrapped in the client module. Using a raw `wl_registry_listener` gives a single intercept point for all globals — both `zwlr_layer_shell_v1` and `wl_output` — with a simpler control flow. The QtWayland-generated `QtWayland::zwlr_layer_shell_v1` wrapper class is still used after binding; only the registry enumeration is raw.

Alternative considered: subclass `QWaylandClientExtension` for the shell global, then use a separate raw listener for outputs. This splits logic across two objects and requires coordination between them. Rejected for unnecessary complexity at this stage.

### 3. `QPlatformNativeInterface` for `wl_surface` extraction

Qt does not expose `wl_surface` directly on `QWindow`. The canonical Qt6 approach for Wayland client integrations is `QPlatformNativeInterface::nativeResourceForWindow("surface", window)`. This is the same pattern used by `xdg-shell` integrations inside Qt itself (visible in Qt source and in wshell's scaffolding). It is a private API (`Qt6::GuiPrivate` is already linked) but stable across Qt 6.x.

### 4. QML does not access Wayland

All Wayland protocol state management lives in C++. QML components receive no Wayland objects, pointers, or handles. The separation is enforced structurally: QML is loaded _after_ the layer surface is configured and the view is resized; QML has no mechanism to reach the compositor.

This boundary is load-bearing for future sessions: `WorkspaceModel`, `ActiveWindowService`, etc. will be C++ `QObject` singletons exposed to QML via `qmlRegisterSingletonInstance` — QML consumes data, not protocol objects.

### 5. `QGuiApplication` not `QApplication`

`QApplication` initializes the widget subsystem, which loads platform input methods, accessibility trees, and widget-specific platform integrations. None of these are needed for a QML-only shell. `QGuiApplication` is the correct base for `QQuickView`-driven applications and avoids the widget overhead.

### 6. `layer_top` for the bar layer

The bar uses `zwlr_layer_shell_v1::layer_top` (value 2), not `layer_overlay` (value 3). `layer_top` is appropriate for persistent shell UI: it sits above normal application windows but below system overlays (screenshot, screen lock). `layer_overlay` would place the bar above the lock screen, which is incorrect behavior. If a future session requires the bar to remain visible during screen lock, that decision should be revisited explicitly.

## Alternatives Considered

### A. Use `QWaylandLayerSurface` from `Qt6::WaylandCompositor`

Qt provides `QWaylandLayerSurface` in the compositor module. This class is designed for _compositor_ implementations — it represents a surface being _managed_, not a surface being _created_ by a client. Linking `Qt6::WaylandCompositor` into a shell client would introduce the entire compositor framework as a dependency. Rejected: wrong abstraction layer.

### B. Use a QML Wayland extension plugin

Some shells (e.g., older KDE Plasma versions) expose Wayland extension calls directly from QML via custom QML plugins. This makes Wayland calls difficult to trace, test, and reason about. The project's established principle (from `TOPBAR-PLAN.md`) is "C++ only. QML is visual only — no Wayland calls from QML." Rejected: violates architecture constraint.

### C. Use `weston-layer-shell` or other wrappers

Third-party C wrappers exist (e.g., from wlroots). Since Qt's `qt6_generate_wayland_protocol_client_sources()` already generates a usable C++ wrapper from the protocol XML, adding a third-party dependency is unnecessary. Rejected: no benefit over the generated wrapper.

### D. Single combined `LayerShellManager` + `QQuickView` subclass

Merging the Wayland management and the QML view into one class per output would make the per-output type responsible for both protocol state and rendering. Separating them (a manager that owns records, records that contain views) keeps Wayland lifecycle and QML lifecycle independently traceable. Rejected: worse separation of concerns.

### E. `QWindow` instead of `QQuickView`

`QWindow` is lighter and does not start a QML engine. However, we need QML rendering from session 1, and `QQuickView` is the standard entry point for loading a `.qml` file into a native window. Using a raw `QWindow` + manual `QQmlEngine` + `QQuickRenderControl` would give finer control over render scheduling but adds significant boilerplate with no benefit at this stage. Rejected: premature optimization.

## Risks

### R1: Layer surface configure event ordering

**Risk:** The compositor sends a `configure` event asynchronously after `wl_surface_commit`. If the application resizes the `QQuickView` or calls `view->show()` before receiving and acknowledging the configure event, the compositor may disconnect the client with a protocol error.

**Mitigation:** `wl_display_roundtrip()` is called immediately after committing the layer surface. This blocks until all pending server events (including `configure`) have been received and dispatched. Only after the roundtrip — and after `ack_configure` is sent — does the code proceed to resize and show the view. This is a synchronous startup cost (~1–5 ms per output) that is acceptable given the `<1 second` startup requirement (REQ-NF-004).

**Residual risk:** If the compositor sends the configure event in a second roundtrip for some reason (compositor-specific behavior), a second roundtrip may be needed. Test on Hyprland specifically.

### R2: JetBrains Mono font not installed

**Risk:** `font.family: "JetBrains Mono"` falls back to the system default sans-serif if the font is not installed. The clock will still display correctly but will not match the HoloNight aesthetic.

**Mitigation:** The font family assignment in QML is best-effort — Qt does not error on missing fonts. For this skeleton session the visual degradation is acceptable. A future session should bundle the font as a Qt resource or verify installation in the startup check. No runtime crash risk.

### R3: `QT_QPA_PLATFORM=wayland` not set

**Risk:** If Qt selects the `xcb` (X11) platform plugin, `QPlatformNativeInterface::nativeResourceForWindow("surface", ...)` returns `nullptr` and the subsequent `get_layer_surface` call dereferences a null pointer, causing a crash.

**Mitigation:** Document in `README.md` and in `task run` that the binary requires a Wayland session. Add a null check on the `wl_surface` pointer in `createBar()` and log a fatal message if it is null. The binary is explicitly out of scope for X11 (REQ-C-006).

### R4: wlr-layer-shell protocol instability

**Risk:** The protocol is named `unstable-v1` — the Wayland protocol version may change, breaking the XML-generated bindings.

**Mitigation:** The XML file is pinned at `protocols/wlr-layer-shell-unstable-v1.xml` and committed to the repository. The generated code is derived from this specific version. Protocol upgrades require an intentional update of the XML and a rebuild — there is no silent breakage. The protocol has been stable in practice since 2019 and is widely adopted across the wlroots ecosystem.

### R5: Output ordering is non-deterministic

**Risk:** `wl_registry` global events arrive in compositor-defined order. The order of outputs in `outputs_` may differ across sessions or compositor restarts, causing bar instances to be associated with "wrong" outputs in display logs.

**Mitigation:** For this session, ordering does not matter — each bar is independent and identical. Future sessions involving per-output workspace state (session 2) will need to correlate outputs by name (via `wl_output.name` event or `xdg-output-unstable-v1`). This is deferred; no action required in `topbar-skeleton`.

### R6: `wl_display_roundtrip()` blocking the Qt main thread at startup

**Risk:** Blocking the main thread during startup delays the first frame. If the compositor is slow to respond, this could violate the `<1 second` startup requirement (REQ-NF-004).

**Mitigation:** `wl_display_roundtrip()` is a single kernel socket read with the compositor; on a local Unix socket this completes in microseconds under normal conditions. Two roundtrips occur at startup (one for globals discovery, one per output for the configure event). For 2–3 outputs this is well within the 1-second budget. Async initialization using `QSocketNotifier` on the Wayland fd is an optimization deferred to a later session if profiling shows a problem.
